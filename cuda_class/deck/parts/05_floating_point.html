ULP: a distância até o número representável vizinho. As funções da CPU (glibc) e da GPU são implementações diferentes.

  • medido, sem FMA (--fmad=false): em FP64, a mesma imagem (e 7,5% mais ciclos); em FP32, outra imagem
  • por isso, na estrela: FP64 dá os mesmos bits na CPU e na GPU; FP32 move 3·10⁻⁴ dos fótons de pixel (veremos na parte 9)

Precisão também é escolher a conta: o nosso código


static inline HD real sine_from_cosine(real cosine) {
    real sine_squared = (1 - cosine) * (1 + cosine);   // não 1 - cosine * cosine
    return sine_squared > 0 ? real_sqrt(sine_squared) : 0;
}
  • perto do polo, \(\cos \to 1\): \(1 - \cos^2\) subtrai dois números quase iguais e perde os bits que importam
  • \((1-\cos)(1+\cos)\) é a mesma conta, com o mesmo custo, e guarda a diferença pequena exata: até ~400× melhor no pior caso
  • o mesmo nas manchas: comparamos a corda ao quadrado, \(|p - s|^2 < 4\sin^2(r/2)\), em vez de \(\cos\) contra \(\cos r\), ambos perto de 1

Monte Carlo perdoa muito: cada fóton é uma conta curta, e a imagem é uma contagem inteira. O que importa é não introduzir viés.
