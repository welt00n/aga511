I. O modelo de execução

O que o guia diz

  • Threads formam blocos (até 1024 threads), blocos formam o grid; um warp são 32 threads que executam uma instrução comum de cada vez (1.2.2, 3.2.2.1).
  • Todos os threads de um bloco rodam num único SM; os blocos rodam em qualquer ordem, sem garantia de escalonamento entre eles (1.2.2.1, 2.3.7).
  • O lançamento é assíncrono; cudaMemcpy é síncrono (2.1.3, 2.1.4). Não há mecanismo para sincronizar blocos dentro de um kernel comum (2.3.6).
  • O lançamento cooperativo é atômico: se a chamada funciona, todos os blocos entram juntos (4.4.8).

No nosso código

// EP4/engine/gpu/gpu.cu: lançar exatamente o que cabe, todos juntos
cudaOccupancyMaxPotentialBlockSize(&grid, &threads_per_block, trace_photons, 0, 0);
cudaOccupancyMaxActiveBlocksPerMultiprocessor(&blocks_per_sm, trace_photons, threads_per_block, 0);
blocks = blocks_per_sm * sms;
cudaLaunchCooperativeKernel(trace_photons, blocks, threads_per_block, args, 0, 0);

__global__ void trace_photons(...) {
    if (!is_allowed(sm_id(), sm_work)) return;   // só os n SMs escolhidos trabalham (%smid)
    take_chunks_until_none_left(...);            // a fila: atomicAdd(&next_chunk, 1)
}

Threads persistentes (o nome é de Stanford, CS149): em vez de um thread por fóton, um thread por vaga nos SMs, e uma fila de pedaços de 1024 fótons. É o grid-stride loop do guia (2.3.3.8) com a divisão decidida em tempo de execução: quem termina antes pega mais.

II. Ponto flutuante

O que o guia diz

  • As GPUs seguem o IEEE 754-2019, sem modo de arredondamento dinâmico e sem exceções (5.6.3).
  • Multiplicações e somas são fundidas (FMA) por padrão; --fmad=false desliga (5.6.3).
  • As funções matemáticas da CPU e da GPU são implementações independentes; diferenças não significam que a GPU esteja errada (5.6.1.8, 5.6.4). Erro máximo: sin, cos 2 ULP; atan2f 3; cbrt 1; sqrt e as operações básicas 0 (5.6.7).
  • FP32 : FP64 é 2 : 1 na compute capability 8.0 (A30) e 64 : 1 na 12.0 (o laptop) (5.1).

No nosso código

// EP4/engine/physics/real.cuh: a mesma conta, sem cancelamento perto do polo
static inline HD real sine_from_cosine(real cosine) {
    real sine_squared = (1 - cosine) * (1 + cosine);   // não 1 - cosine * cosine
    return sine_squared > 0 ? real_sqrt(sine_squared) : 0;
}

"Local" é o escopo, não o lugar: fica na memória do device, com a latência da global (2.3.3.4). O guia ensina histogramas na memória compartilhada de cada bloco, somados depois na global com atômicos (2.3.3.8); a ordem dos atômicos em ponto flutuante varia entre execuções (5.6.8).

No nosso código

// EP4/engine/gpu/gpu_image.cuh: a imagem é um histograma de fótons
static inline __device__ void count_photon_atomic(PixelCount *counts, unsigned long long pixel) {
    atomicAdd(&counts[pixel], 1u);    // 1,26·10⁹ contagens: direto na memória global
}

1024² pixels × 300 quadros × 4 observadores = 1,26·10⁹ contagens: 5 GB, que não cabem em 100 KB de memória compartilhada. Com bilhões de endereços, dois fótons quase nunca disputam o mesmo pixel. E as contagens são inteiras: somadas em qualquer ordem, dão o mesmo número, uma das razões de a imagem sair bit a bit.

IV. A ocupação

O que o guia diz (2.3.7)

A ocupação é a razão entre os warps ativos e o máximo de warps de um SM. "É uma boa prática ter a ocupação tão alta quanto possível"; limitar os registradores "pode resultar num ganho líquido de desempenho".

No nosso código

Os registradores por thread decidem quantos warps cabem: 65 536 / (⌈r/8⌉ · 8 · 32), no máximo 48 no laptop e 64 na A30. Para testar o guia, compilamos o kernel com -maxrregcount de 80 até 32 e medimos em ciclos, que não dependem do clock.

No laptop, mais ocupação não foi mais rápida. Tirar registradores custa instruções antes mesmo de derramar (FP32 a 55 registradores, nada derramado: 4,7% mais instruções, 1,1% mais ciclos), e depois cada derramamento é uma escrita e uma leitura na memória local. Mais warps só pagariam se o SM ficasse parado esperando latência; aqui ele espera as 2 unidades FP64 (FP64 é 16,2× mais lento que FP32, e o código FP64 tem 1 063 NOPs de espera em 2 744 instruções). Na A30, com FP64 rápido e 96 registradores (ocupação ≤ 0,33), a resposta pode ser outra: [A30: a medida].
